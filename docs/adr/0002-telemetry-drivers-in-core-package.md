# ~~Telemetry drivers ship inside laravel/ai, not as a separate package~~

> **Superseded by [ADR-0003](./0003-telemetry-extracted-to-separate-package.md).** The decision below was reversed: telemetry now lives in `vinitkadam03/laravel-ai-telemetry`. The original reasoning about Scout/Mail/Filesystem analogies does not hold because those bundled drivers implement framework concerns (mail transport, storage) — telemetry is orthogonal observability infrastructure. Taylor Otwell's actual pattern for observability is a separate package (Telescope, Pulse, Horizon), not a bundled driver.

All telemetry drivers (Null, Log, OTLP) live in `laravel/ai`. The `open-telemetry/sdk` dependency required by the OTLP driver is listed in `suggest`, not `require` — the OTLP driver class loads regardless but throws a descriptive exception if the package is absent. This matches the pattern used by Scout (Algolia driver in core, `algolia/algoliasearch-client-php` optional), Mail (Mailgun driver in core, `symfony/mailgun-mailer` optional), and Filesystem (S3 driver in core, `league/flysystem-aws-s3-v3` optional). A separate `laravel/ai-telemetry` package was considered but rejected: the listener cannot be separated from the events it listens to, the Null driver must always resolve in the container, and driver adapters are not full applications warranting their own package lifecycle.
